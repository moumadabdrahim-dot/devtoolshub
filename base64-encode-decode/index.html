What is Base64 Encoding?

Base64 is a binary-to-text encoding scheme that converts binary data into a string of printable ASCII characters. It uses a 64-character alphabet: A-Z, a-z, 0-9, +, and /, with = used for padding. The name "Base64" comes from this 64-character set.

Base64 encoding is essential when you need to transfer binary data through channels that only support text — such as email (MIME), HTML (data URIs), JSON payloads, or URL query parameters. It is not encryption and provides no security; it is purely a transport encoding.

How Base64 Works

The encoding process follows these steps:

  1. Read 3 bytes (24 bits) of binary data at a time.
  2. Split into 4 groups of 6 bits each (since 2⁶ = 64 possible values).
  3. Map each group to one character from the Base64 alphabet.
  4. Pad with = if the input is not a multiple of 3 bytes. One remaining byte produces 2 Base64 characters + ==; two remaining bytes produce 3 characters + =.

This 3-to-4 byte ratio means Base64-encoded data is always approximately 33% larger than the original. For example, a 300-byte file becomes ~400 characters when Base64-encoded. 

Original:  "Hi!"  →  72 105 33  (3 bytes)
Binary:    01001000 01101001 00100001
Split 6:   010010 000110 100100 100001
Base64:    S       G       k       h
Result:    "SGkh"

When to Use Base64

  • Data URIs — Embed small images, fonts, or SVGs directly in HTML and CSS using data:image/png;base64,... to reduce HTTP requests.
  • API authentication — HTTP Basic Authentication encodes username:password as Base64 in the Authorization header.
  • JWT tokens — JSON Web Tokens use Base64URL encoding for the header and payload segments.
  • Email attachments — MIME encoding uses Base64 to embed binary attachments in text-based email messages.
  • Binary data in JSON — Since JSON does not support binary types, binary data (images, files) is encoded as Base64 strings.
  • Storing keys and certificates — PEM-encoded certificates and SSH keys use Base64 to represent binary cryptographic data as text.

Base64 vs Base64URL

Standard Base64 and Base64URL encode the same data but differ in characters used:

FeatureBase64 (Standard)Base64URL
AlphabetA-Za-z0-9+/A-Za-z0-9-_
PaddingUses = paddingPadding omitted
URL-safeNo — + and / need percent-encodingYes — safe in URLs and filenames
Used inMIME, email, PEM certs, data URIsJWTs, URL params, OAuth tokens

The key difference: standard Base64 uses + and / which have special meaning in URLs. Base64URL replaces them with - and _, and drops the trailing = padding, making the string safe to use directly in URLs without encoding.

Frequently Asked Questions

Is Base64 encoding the same as encryption?

No. Base64 is a reversible encoding scheme, not encryption. It provides no confidentiality or security — anyone can decode a Base64 string. If you need to protect data, use proper encryption (AES, RSA) before optionally Base64-encoding the ciphertext for transport.

Why does Base64 increase the size of data?

Base64 represents every 3 bytes of binary input as 4 ASCII characters. This 4/3 ratio means the output is approximately 33% larger. Additionally, line breaks may be inserted every 76 characters (in MIME), further increasing size. This overhead is the trade-off for safe transport over text-only channels.

Can I Base64-encode any file type?

Yes. Base64 works on raw binary data regardless of the file format. You can encode images (PNG, JPEG, SVG), PDFs, ZIP archives, executables — any file type. The "File" tab in this tool lets you upload any file and get its Base64 representation. Keep in mind that large files will produce very long Base64 strings.
