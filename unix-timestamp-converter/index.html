What is a Unix Timestamp?

A Unix timestamp (also called Epoch time, POSIX time, or Unix Epoch time) is a system for tracking time as a single number: the total number of seconds that have elapsed since January 1, 1970, 00:00:00 UTC — a moment known as the "Unix Epoch." It does not account for leap seconds.

This simple, timezone-independent number is the backbone of timekeeping in virtually every operating system, programming language, database, and web API. When you see timestamps like 1711545600 in logs, databases, or API responses, that is Unix time at work.

How Unix Time Works

The concept is elegant in its simplicity: count seconds from a fixed point. At the Unix Epoch (Jan 1, 1970 00:00:00 UTC), the timestamp is 0. One hour later, it is 3600. One day later, it is 86400. Right now, the timestamp is in the billions.

Because Unix time is just a number, it avoids the complexities of time zones, daylight saving time, calendar formats, and locale-specific date representations. Any system can convert the same number to the correct local time for its timezone. 

// JavaScript
const now = Math.floor(Date.now() / 1000);
console.log(now); // e.g. 1711545600

// Python
import time
now = int(time.time())

// PHP
$now = time();

// Bash
date +%s

The Year 2038 Problem

Many older systems store Unix timestamps as a 32-bit signed integer, which has a maximum value of 2,147,483,647 — corresponding to January 19, 2038, at 03:14:07 UTC. One second later, the integer overflows and wraps to a negative number, which these systems would interpret as December 13, 1901.

This is known as the Y2K38 Bug or the Epochalypse. Modern systems have largely mitigated this by switching to 64-bit integers, which can represent dates up to approximately 292 billion years in the future — effectively solving the problem forever. However, legacy embedded systems, firmware, and old databases may still be at risk.

Frequently Asked Questions

What is Unix epoch time?

Unix epoch time counts the number of seconds since January 1, 1970, 00:00:00 UTC. It is a timezone-independent way to represent a specific moment in time as a single number, and it is used by virtually all programming languages and operating systems.

Is a Unix timestamp in seconds or milliseconds?

The traditional Unix timestamp is in seconds (10 digits, e.g. 1711545600). However, JavaScript's Date.now() and many modern APIs use milliseconds (13 digits, e.g. 1711545600000). This tool supports both — use the toggle to switch.

Can Unix timestamps represent dates before 1970?

Yes. Dates before the epoch are represented as negative numbers. For example, the Moon Landing on July 20, 1969 has a timestamp of -14182940. JavaScript's Date object handles negative timestamps correctly.
