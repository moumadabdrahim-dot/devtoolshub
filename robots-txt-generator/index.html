What is robots.txt?

robots.txt is a plain text file placed at the root of your website (e.g. https://example.com/robots.txt) that instructs web crawlers which parts of the site they are allowed — or not allowed — to access. It follows the Robots Exclusion Protocol, a de facto standard since 1994, now formalised as RFC 9309.

Every major search engine (Google, Bing, Yandex, Baidu) respects robots.txt directives. However, it is an advisory mechanism — malicious bots can ignore it.

robots.txt Syntax Explained

# Comment — ignored by crawlers
User-agent: *        # Which crawler this block applies to
Disallow: /admin/    # Block this path
Allow: /admin/public/ # Allow a sub-path (overrides Disallow)
Crawl-delay: 10      # Wait 10 seconds between requests

Sitemap: https://example.com/sitemap.xml
  • User-agent — * matches all bots, or specify a name like Googlebot
  • Disallow — paths the bot must not crawl; empty value means "allow all"
  • Allow — explicitly permit a sub-path within a disallowed parent (Google/Bing extension)
  • Crawl-delay — seconds between requests (respected by Bing, Yandex; ignored by Google)
  • Sitemap — absolute URL to your XML sitemap; can appear multiple times

Common robots.txt Mistakes

  1. Blocking CSS/JS files — Google needs to render your page. Blocking stylesheets and scripts prevents proper indexing and can hurt rankings.
  2. Using robots.txt to hide pages — Disallow prevents crawling, not indexing. If external sites link to a disallowed page, Google may still index the URL. Use <meta name="robots" content="noindex"> instead.
  3. Forgetting the trailing slash — /admin blocks the file /admin. /admin/ blocks the directory and everything inside it. Usually you want the slash.
  4. Multiple robots.txt files — Only /robots.txt at the domain root is valid. Files in subdirectories are ignored.
  5. Case sensitivity — Paths are case-sensitive. /Admin/ and /admin/ are different.

Frequently Asked Questions

What is robots.txt?

robots.txt is a plain text file at your website's root that tells search engine crawlers which pages or directories they may or may not access. Every major search engine respects these directives. The file follows the Robots Exclusion Protocol, formalised in RFC 9309.

Can robots.txt prevent Google from indexing a page?

No. robots.txt prevents crawling but not indexing. If other sites link to a disallowed URL, Google may still show it in search results (with no snippet). To prevent indexing entirely, use <meta name="robots" content="noindex"> or the X-Robots-Tag: noindex HTTP header.

Where do I put the robots.txt file?

Place it at the root of your domain: https://example.com/robots.txt. It must be accessible via HTTP at that exact path. Files in subdirectories (like /blog/robots.txt) are not valid and will be ignored by crawlers.

Does robots.txt affect website security?

No. robots.txt is publicly accessible and advisory only — malicious bots will ignore it. Never use it as a security measure. It is meant for controlling legitimate search engine crawlers, not for hiding sensitive content. Use authentication, firewalls, and proper access controls for security.
