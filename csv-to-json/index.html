What is CSV?

CSV (Comma-Separated Values) is one of the oldest and most widely used formats for storing and exchanging tabular data. Each line in a CSV file represents a row, and each value within a row is separated by a delimiter — most commonly a comma. CSV files can be opened in spreadsheet applications like Microsoft Excel, Google Sheets, and LibreOffice Calc.

Despite its simplicity, CSV remains the dominant format for data exports, database dumps, analytics reports, and data migration between systems. Converting CSV to JSON is a common task when you need to consume spreadsheet data in web applications, APIs, or NoSQL databases like MongoDB.

CSV Format Rules

The CSV format (defined in RFC 4180) has a few important rules that affect parsing:

  • Quoting — Fields containing the delimiter character, newlines, or double quotes must be enclosed in double quotes. For example: "New York, NY".
  • Escaping quotes — A literal double quote inside a quoted field is represented by two consecutive double quotes: "He said ""hello""" becomes He said "hello".
  • Line endings — CSV files may use \r\n (Windows), \n (Unix/Mac), or \r (old Mac). This tool handles all three.
  • Empty fields — Two consecutive delimiters (,,) represent an empty field. This tool preserves them as empty strings or null values.
  • Header row — The first row typically contains column names, but this is a convention, not a requirement. Use the "First row is header" option to control this behavior.

Common CSV Issues

If your conversion produces unexpected results, check for these common problems:

  • Wrong delimiter — European systems often use semicolons instead of commas because commas are used as decimal separators. Switch to "Semicolon" in the delimiter dropdown, or use auto-detect.
  • Character encoding — If you see garbled characters (like Ã© instead of é), your file may use a different encoding. Save it as UTF-8 before converting.
  • Inconsistent column counts — Rows with fewer or more values than the header row can cause misaligned data. Check your source data for missing or extra delimiters.
  • Numbers as strings — Leading zeros (like zip codes 07302) will be preserved as strings. If you need numeric types, post-process the JSON output.
  • BOM (Byte Order Mark) — Some editors add an invisible BOM character at the start of UTF-8 files. This can cause the first column name to appear prefixed with unusual characters.

Frequently Asked Questions

Is my CSV data safe when using this converter?

Absolutely. All parsing and conversion happens entirely in your browser using JavaScript. No data is sent to any server, stored in any database, or logged. You can verify this by checking the Network tab in your browser's developer tools — zero outbound requests are made during conversion.

Can this tool handle large CSV files?

Yes. This tool comfortably handles CSV files up to 10 MB with thousands of rows. For very large files (50 MB+), performance depends on your device's available memory and browser. If you experience slowness, consider splitting the file into smaller chunks.

What delimiters does this tool support?

The tool supports comma (,), semicolon (;), tab (\t), and pipe (|) delimiters. The auto-detect feature analyzes the first few lines of your data and selects the most likely delimiter automatically. You can always override the detection by selecting a specific delimiter from the dropdown.
